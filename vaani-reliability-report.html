Verdict

Good engineering base. Incomplete reliability system.

Luna explored current code read-only. I checked release metadata, CI, PR review findings, critical code paths, and Wispr Flow's official recovery and incident material.

HEAD e302cfe is much stronger than shipped v1.1.3. It adds native capture with two-second pre-roll, physical microphone selection, multi-provider and local Whisper failover, silence-aware long-form chunking, content guards, baseline-aware insertion verification, structured traces, Keychain storage, and real CI. That is serious progress. Still, Vaani's weakest layer begins after something goes wrong. Audio retention is off by default, History retry only reinserts existing text, provider work is not cancellable, sleep and audio-route recovery lack proof, and several current UI or persistence paths can delete credentials or report failure after data was written. Wispr Flow is not flawless, especially during its June 2026 reliability incidents. It does set a stronger recovery expectation through retained audio, retryable failed transcriptions, clipboard fallback, wake recovery, microphone handoff, and visible troubleshooting. Vaani's route beyond Flow is clear: make local recovery authoritative, prove delivery in real apps, and treat every failed dictation as recoverable work rather than a dead end.

Benchmark

Do not copy Flow. Beat its recovery contract.

Flow's 2026 record includes outages and accuracy regressions. Its useful benchmark is how it handles failure, not a myth that it never fails.

What Wispr Flow currently does better

  • Automatically retries failed transcription, then exposes manual retry from History.
  • Retains desktop audio locally for up to 14 days, subject to retention policy.
  • Copies completed text to clipboard when desktop insertion fails.
  • Uses nearby app and window context to improve names, formatting, and tone.
  • Documents wake recovery, microphone ranking, clamshell switching, and routed or virtual inputs.
  • Publishes incident history and claimed 99.9% dictation uptime after June 2026 failures.

Where Vaani has a better long-term position

  • Local whisper.cpp can keep transcription working without internet or vendor uptime.
  • Groq, OpenAI, Deepgram, and local providers reduce single-vendor dependence.
  • Two-second pre-roll, physical-device filtering, and native capture address clipped starts directly.
  • Deterministic cleanup and content guards can reject destructive formatter output.
  • Local traces and build IDs support reproducible diagnosis without mandatory telemetry.
  • Keychain storage and user-controlled local operation offer a stronger privacy story.

Parity gaps

After bug fixes, five product systems still need proof.

These gaps explain why 392 passing tests cannot support a Wispr Flow parity claim.

Durable failed-dictation recovery

saveRecordings defaults false. History retry reinserts stored text instead of re-transcribing audio. Failed cloud work can become unrecoverable.

Cancellable provider work

Long clips share a scaled deadline, but provider APIs receive no AbortSignal. Timed-out work can continue and spend quota after user-visible failure.

Sleep, wake, and route-change recovery

Capture has pre-roll, warm mode, physical-device filtering, and restart after native errors. No measured sleep, wake, dock, Bluetooth, or unplug recovery contract exists.

Real app insertion acceptance

Local trace scoring uses readable accessibility values and excludes unreadable baselines. Rich editors, terminals, browsers, and delayed renderers still need visual end-to-end trials.

Bounded nearby-text context

Current app context is bundle classification plus app profiles. It does not use bounded nearby document text for names, grammar continuation, or tone.

Improvement path

Build recovery first. Add intelligence after delivery is boring.

Durability order matters. A smarter transcript that vanishes is worse than plain text safely waiting in a recovery queue.

Release gate

Close defects and establish trustworthy acceptance

  • Fix seven verified release-gate items. Add focused failure-injection and browser event-order tests.
  • Resolve the Intel support mismatch by shipping x64 artifacts or narrowing the stated system requirements.
  • Run 16-hour endurance, 500 overlay show cycles, 500 sleep/wake cycles, and a 20-app insertion matrix.
  • Keep PR CI green. Add push-to-main CI and pin action SHAs.
Next 30 days

Make every dictation recoverable

  • Add a local session journal before transcription begins. Store status, target, provider attempts, audio handle, transcript, and insertion result.
  • Retain encrypted audio for a short user-controlled window after failure. Default to local-only and delete after confirmed delivery.
  • Upgrade History retry to re-transcribe audio, rerun formatting, and retry insertion. Keep plain reinsertion as a separate action.
  • Pass AbortSignal through cloud providers and local Whisper. Stop all work at deadline or cancellation.
  • Add explicit clipboard fallback and a persistent recovery queue when insertion cannot be verified.
Next 90 days

Prove hardware, app, and language reliability

  • Build a frozen audio corpus for accents, technical names, noise, short phrases, and 3, 10, and 20-minute dictation.
  • Add mic ranking and seamless handoff for built-in, USB, Bluetooth, docked, clamshell, and virtual routes.
  • Add bounded nearby-text context with password-field exclusion, per-app controls, and local redaction tests.
  • Maintain per-app insertion contracts. Test native AX, clipboard, keystroke, rich editors, terminals, and non-QWERTY layouts.
  • Show local reliability reports for capture, STT, formatting, insertion, recovery, and latency. No mandatory telemetry needed.
Beyond parity

Use local authority to remove vendor failure from the user experience

  • Guarantee local transcription fallback whenever a healthy model is installed, even during cloud outage or account failure.
  • Replay failed sessions deterministically from retained audio and build metadata.
  • Add offline command editing and deterministic formatting before optional cloud formatting.
  • Let users choose privacy profiles for local-only, cloud-fast, or redundant cloud plus local rescue.
  • Treat delivery as a transaction. Text is inserted, queued for recovery, or copied with a clear status. Never silently lost.
